# Independent geographic input evaluation

This specification is fixed after source schema and coverage checks and before computing policy outcomes on the new source. It extends the unchanged baseline-protection protocol, not its method-selection rules.

The City of Palo Alto official source contains 259,415 sessions through December 2020 and 47 station names, with charging duration, energy and coordinates. It was not used in the prior method development. The official Boulder source was checked and its latest available session remained in November 2023. Source selection was based on access and schema, not on policy performance.

Use January 2017 through December 2020. Retain station names with at least 100 valid sessions during 2017 and 2018 and valid training-period coordinates. This eligibility rule never uses 2019 or 2020 activity. Use only positive finite energy, valid start time and a positive charging duration no longer than 48 hours and no longer than the reported connection duration. Exclude records failing these rules, retain counts by rule and preserve the downloaded original locally. Session-hour energy is reconstructed uniformly over the valid charging interval, with energy accounting at the study boundary. Exact duplicate records across the analysis fields are removed and counted.

Training-period station means and resource budgets use only 2017 and 2018. Coordinates and a four-neighbour graph are determined from the retained training stations. Calendar year 2020 is the external demand evaluation period. Calendar year 2019 is not used to retune the guard or to choose between methods.

All tested restoration policies share the same issued forecasts. The primary forecast input uses the already selected Boulder GraphGRU checkpoint, unchanged learned parameters and its original training normalization, with the nonlearned adjacency buffer replaced by the external station graph. This is a retrospective geographic transfer experiment, not a claim of deployment in 2020 before training occurred. A second, separately labelled input uses the observed values at the same hours in the preceding week. Both are fixed here, both are reported, and neither is selected from external policy outcomes.

The central coefficients, finite uncertainty set, objective weights, guard margin and execution rules are transferred without fitting to external outcomes. The source benchmark's abstract outage, packet and repair models are retained. The electrical network remains the same SMART-DS feeder with the declared station embedding. Route distances use the external station coordinates. Packet response surfaces remain constructed training-period benchmark inputs, mapped deterministically by station index, not Palo Alto packet measurements. This experiment tests independent geographic demand and station geometry, not a jointly observed local infrastructure disaster.

For each forecast input, run 1,024 paired external scenarios in every predeclared validation condition and in the electrical stress condition. Preserve the original four threat classes and use a fixed scenario random state of 202609052. Run both common-route groups and retain matched, central, robust, the frozen protected policy, and the observation-supported score where defined. No margin, weight, matrix, forecaster or filtering rule is chosen using these policy results.

The external adoption check uses the original-condition paired guard-minus-central difference with the predeclared 0.05% matched-cost margin. A one-sided 97.5% bootstrap upper bound must be negative in both fixed forecast inputs. All error-condition outcomes, tail metrics, positive excesses and constraint checks are reported. Failure of this check prevents promotion to the primary method, even if earlier tests were favourable.

The raw municipal table includes fields not needed for the study, such as user identifiers. They are neither used nor included in the public processed inputs. Source rights follow the City's Open Data Terms of Use, not an invented CC0 licence. Retain attribution and a stable original download route. Public analysis inputs contain station-level aggregates, source provenance and transformation code.
